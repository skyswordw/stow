Browser is the default opening experience**, **Actions is the English public name** for

## Proposed composition and action contract

**Browser — revised content-first direction:** the earlier three-pane study retained too much
permanent structure. The user's new feedback calls for reallocating space, not only reducing
padding. In the captured ArcZip full-window state, the main file list and right detail area
are visible without a permanent left archive/folder pane. This observation does not establish
all of ArcZip's possible layouts or defaults.

Current Stow source requests a sidebar minimum/ideal/maximum of **220/248/320 pt** and an
Inspector of **240/280/360 pt**. Their ideal widths total **528 pt**, before dividers; these are
source sizing hints, not measured window allocations. The left archive card and the unselected
Inspector duplicate information while both reduce room for filenames and file columns.

Proposed structure for Claude Code:

- Make the file workspace the primary continuous surface. Explore **files plus optional
  preview**, with a list-only focus state and an optional folder tree for deep archives.
  Three visible panes remain available when deliberately useful; the design should not require
  them to establish archive identity or expose essential commands.
- Move archive identity and a concise information affordance into the title/navigation region;
  provide sizes, ratio and detailed facts once in Archive Info. Keep Checkup and explicit password
  entry discoverable with both side panes closed. Do not move security state into an obscure menu.
- Use breadcrumbs, Back/Forward and Up for ordinary navigation. A labelled folder control reveals
  the tree when needed; no large identity/statistics card inside that tree. **Search must stay
  available with the tree hidden**; current `.searchable(placement: .sidebar)` needs a new host.
- Let the preview pane use content-appropriate height and bounded width. Text needs a readable
  excerpt and compact facts, rather than a fixed empty poster area. Images/PDFs may need more
  space. Keep preview and Quick Look distinct, and avoid duplicating the Actions buttons there.
- Keep pane controls discoverable and explicit. Avoid automatically opening/closing panes on
  every selection or file-kind change. Preserve user choices; exact initial visibility,
  persistence and responsive breakpoints remain implementation proposals for review.

The [revised structure study](evidence/2026-10-24/browser-content-first-structure-study.jpg)
shows the proposed file/preview composition with folder navigation hidden. Its controls explore
both optional panes. It supersedes the earlier three-pane studies for **composition**, while
retaining the user-confirmed floating Actions direction. It is not native or final visual approval.

Do not merely lower `SidebarView.minWidth`: its current minimum prevents wrapped ArchiveCard
content from causing an AppKit constraint-update loop. Restructure the pane content and test
geometry as a functional change. Preserve navigation/history, focus, search, drop destinations,
staged edits and ongoing operation targets when panes are toggled or reflowed.

**Toolbar:** prioritize navigation, view mode and the archive-level action. Give Glance a
stable visible route coordinated with #159. Secondary tools can use deliberate menus. Explain
Extract All versus selected extraction through wording and scope; avoid equally prominent
duplicates competing across the window. Preserve menu/keyboard routes.

**Actions:** the user confirmed the coherent floating bottom group. The earlier fixed-bottom
study is historical exploration and is no longer a competing implementation direction.
Keep selection scope and the primary target stable, reserve room above path/edit bars, and
let long-name metadata yield before essential action labels. Claude should evaluate a small
Actions label/matching Settings symbol. Branding must not obscure concrete action verbs.
Size the floating group around its contents; avoid turning it into another full-width panel.

Keep Extract as the existing default primary. App/font/PKG/nested-archive suggestions are
explicit alternatives; never silently promote installing executable content to the default.
More contains applicable hidden suggestions; hiding a suggestion does not disable a capability.
Maintain the current operation target when selection changes. Preserve nested-result routing,
keyboard focus, history, staged edits and credentials across Browser/Glance transitions.

Reference structure studies: [floating Actions](evidence/2026-10-24/actions-floating-structure-study.jpg)
and [anchored alternative](evidence/2026-10-24/actions-anchored-structure-study.jpg). These are
non-native, unapproved composition examples, not Stow screenshots or final visual designs.
The floating group is now confirmed; the permanent three-pane shell is superseded above.
Claude owns visual refinement. Local prototype
checks covered changing file type, multiple selection, retaining an operation's scope after
selection changes, cancellation, and both variants at 320-point content width without horizontal
overflow. These checks do not establish native app behavior or full keyboard/VoiceOver acceptance.

**Public naming:** #161 updates Settings, customization menu, accessibility hints and current
help/website copy to Actions. Existing Swift types, files, routing cases and UserDefaults keys
may keep NextSteps names. Preserve hidden suggestions and explicit saved preferences. Update
website screenshots after implementation rather than claiming the proposed UI has shipped.

## Required state coverage

| State or content | Interaction contract | Presentation goal |
| --- | --- | --- |
| Nothing selected | Extract All keeps whole-archive scope; do not invent a selected target. | Quiet, useful archive context without repeated statistics or a fake selection bar. |
| One plain file / folder | Preview applicability and selection extraction remain truthful. | Recognizable name/type/scope; one clear primary action. |
| Multiple / mixed types | Show count; only applicable actions are enabled. | Stable group and readable scope; overflow without clipped action labels. |
| App / fonts / PKG | Keep explicit installation, signature warnings, replacement and running-app refusal. | Concrete verbs and item identity; install is not silently made the default. |
| Nested archive / search hit | Open Inside or Show in Archive navigates to the actual target. | Separate archive identity, current location and search-result scope. |
| Public filenames, locked content | Browsing remains possible; explicit lock/password route; no prompt on hover. | Labelled lock and useful preview explanation without claiming successful decryption. |
| Password / verification / retry | Cancel prevents late credential saving or Quick Look reopening; mixed passwords stay supported. | Field error nearby; stable targets; no success before a verified read. |
| Pending edits / external change | Visible review/save/discard; preserve original, native Undo/Redo and stale-file protection. | Persistent concise status; Glance hands complex edits to a visible full editor (#156). |
| Preparing / running / stopping | Correct original target, progress only when known, reachable cancellation. | Reuse ActivityCapsule; retain operation identity when selection changes. |
| Done / cancelled | Report actual output; Show in Finder only for placed files; cancel is not failure. | Restrained feedback; no misleading success color on partial work. |
| Recoverable error / conflict | Typed advice, valid recovery, Copy Details, safe Return/Escape behavior. | Reuse PromptCard; preserve focus and entered values; no error code as the main heading. |
| Empty / no search results | Distinguish empty location from no matches and unreadable archive. | Concrete next action with restrained chrome; no fabricated files. |

## Supporting surfaces

- **Glance (#159):** persistent archive/location context, distinct Up/history, discoverable
  full/compact switches, readable selected scope and pending-edit handoff. Functional contracts
  are #156 (editing), #157 (context/navigation), #158 (materials/accessibility). Do not rebuild
  the existing feature as a second Mini subsystem.
- **Pack (#153):** sentence for common choices, advanced controls for compression, parts,
  compatibility and password capabilities. Single shared state; visible effective settings,
  reset-to-purpose behavior and output estimates labelled as estimates. #151 owns custom
  split sizes/units/validation; #152 owns per-job overrides. #155 already handles token
  affordances, More Options summary, password checks and short-screen scrolling; review its
  functional gating and native keyboard/IME behavior before declaring acceptance.
- **Tray/install (#154):** preserve whole-panel drop feedback, duplicates, destination clarity,
  inline validation and named progress. Avoid a second redesign. The PR flags partial-copy
  advice and adds remembered multi-folder destinations; functional review remains necessary.
  Real drag/scroll/fade and VoiceOver speech are not proved by snapshots.
- **Settings (#162):** prefer stable category navigation and scrollable details. Group Actions,
  Glance and preview preferences coherently; show a contextual example; explain reset scope.
  Keep credentials, folder grants and installation security explicit. Preserve deep links,
  stored values and actual macOS language behavior.
- **Trust/recovery (#104):** refine the existing lock, password, preparation, conflict and failure
  components consistently. No new prompt system. Keep archive and affected item identity,
  truthful encryption language and safe default choices. #93's AX crash remains independent.
- **Welcome/sample (#91/#69):** prioritize Open Archive / real drop behavior. A genuine bundled
  example ZIP is the preferred proposal if an example ships; clearly label any remaining
  simulation. Final release entry choice remains open in #91. Keep first use skippable and
  do not add a mandatory onboarding carousel.

Use system type and semantic colors, restrained amber for the primary action, solid content
surfaces and a glass control layer. Resolve separation with alignment and spacing before
extra cards. Status always has words/icons. Maintain readable density and full keyboard/AX
semantics in English and Chinese, light/dark and Increase Contrast. Selection, search, view
switches and keyboard actions stay immediate. Claude owns motion tuning under DESIGN.md;
Reduce Motion/Transparency must retain understandable state and usable targets.
